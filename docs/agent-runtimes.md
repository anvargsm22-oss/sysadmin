# Sysadmin Agent в Claude Code и Codex

У двух сред один мозг и одна инфраструктура. Пользователь может переключаться между
ними; изменения сервера и inventory нельзя выполнять одновременно из двух сессий.
Последняя запись другой сессии — ориентировка, перед действием проверяется реальность.

## Общие источники

| Назначение | Канонический источник | Claude Code | Codex |
|---|---|---|---|
| Персона и безопасность | `CLAUDE.md` + `.claude/agents/references/` | загружает ядро | `AGENTS.md` направляет прочитать ядро целиком |
| Процедуры | `.claude/skills/` | собственный discovery | генерируемые `.agents/skills/` |
| Агент-сисадмин | общее ядро | `.claude/agents/sysadmin.md` | `.codex/agents/sysadmin.toml` |
| Знания | `.claude/knowledge/` | общий источник | общий источник |
| Карта проектов | `agent-config.json` | общий источник | общий источник |
| Инвентарь и память | папка по `projects[].infra_root` | общий источник | общий источник |
| Политики хуков | `.claude/hooks/*.sh` | `.claude/settings.json` | `.codex/hooks.json` → Python-переходник → те же хуки |

Имя `.claude/` сохранено для обратной совместимости. Оно не означает, что Codex должен
запускать Claude CLI. Относительные пути `scripts/`, `references/`, `templates/` внутри
навыка относятся к **канонической** папке этого навыка.

## Установка Codex в существующий проект

1. Открой именно папку `sysadmin/` в Codex. Нужны Git, Python 3.11+ и Bash (на Windows —
   Git for Windows); jq нужен инфраструктурным процедурам. Python-переходник хуков
   использует стандартную библиотеку, дополнительных пакетов не требует.
2. Выполни `python3 scripts/sync-codex.py --check`. В Windows можно использовать
   `python scripts/sync-codex.py --check`. Если точки входа отстают от источников,
   выполни тот же скрипт без `--check`. Он не меняет Claude, серверы, глобальный конфиг
   или приватную папку инфры. Если среда защищает `.agents/` и `.codex/`, используй её
   штатное разрешение на запись; не переносись в другое место ради обхода защиты.
3. Запусти `python3 scripts/test-agent-runtimes.py`. Это локальные тесты: строки с
   опасными командами подаются хукам как данные и не исполняются на сервере.
   `python3 scripts/check-codex-runtime.py` дополнительно спрашивает установленный
   загрузчик Codex: видны ли все навыки и три определения хуков. После выдачи
   доверия добавь `--require-active-hooks`; эта проверка ничего не активирует сама
   и не обращается к модели.
4. Начни новую сессию Codex, проверь наличие навыков через `/skills` и профиля
   `sysadmin`. В CLI открой `/hooks`, просмотри и доверься трём определениям этого
   проекта. Codex пропускает непроверенные пользовательские хуки; наличие файла
   **не доказывает**, что хук активен. В интерфейсе без просмотра/доверия хукам
   включи их через поддерживаемый интерфейс того же локального Codex; до этого
   ограничь работу диагностикой. Не используй флаг обхода доверия.
5. Разреши по штатному запросу среды чтение выбранной `infra/`, SSH-конфига и
   использование существующего ключа. Не выдавай полный доступ к диску ради одного
   сервера. Личные пути и полномочия не записываются в публичный конфиг проекта.

Общий конфиг `.codex/config.toml` включает поддержку хуков и субагентов, но не
меняет модель, провайдера, режим разрешений или песочницу пользователя. Codex 0.160.0
проверен на этой машине; на других версиях проверяй discovery, формат журналов и хуки.
Codex требует доверия к слою конфигурации проекта отдельно от доверия к хукам.

### Windows

`codex.cmd` работает и тогда, когда PowerShell запрещает npm-переходник `codex.ps1`.
Для Bash можно указать `SYSADMIN_BASH` с полным путём к `bash.exe`; переходник умеет
найти обычную установку Git for Windows. `SYSADMIN_PYTHON` используется только
дочерним Bash-процессом хука и указывает на Python, уже запустивший переходник.

Windows-команда хука использует локальный `run-hook.ps1`, UTF-8 и
`-ExecutionPolicy Bypass` **для этого процесса**, не меняя глобальную политику
PowerShell. Если Python не запускается, переходник выдаёт читаемый отказ,
а не молчаливое разрешение.

Изолированный пользователь Codex может не видеть твой SSH-алиас. Сначала проверяй
`ssh -G <alias>`; при необходимости используй явный `-F <путь к .ssh/config>` с
разрешением среды. Диагностический вход: `BatchMode=yes`,
`StrictHostKeyChecking=yes`, `UpdateHostKeys=no`. Не отключай проверку ключа хоста
и не копируй приватные ключи внутрь публичного проекта.

## Выполнение навыков

В Claude остаются `/health-check`, `/sysadmin-init` и другие существующие команды.
В Codex выбирай `$health-check`, `$sysadmin-init` и т. п. либо сформулируй задачу
обычным языком. Вызов навыка не расширяет полномочия на серверные изменения.

Девять явно вызываемых навыков сохраняют эту политику: генератор переводит
`disable-model-invocation: true` в `agents/openai.yaml` с
`allow_implicit_invocation: false`. Для остальных автоматический выбор разрешён.
`allowed-tools` Claude — подсказка переходнику; полномочия Codex определяются
реально доступными инструментами и текущим режимом среды.

Подстановки вида `!` с shell-кодом, параметры `$ARGUMENTS`, вызовы `Skill` и `Agent`
в исходных инструкциях являются соглашениями Claude Code. В Codex:

- код подстановки выполняется явно, результат читается и проверяется;
- параметры берутся из запроса оператора и проверяются по процедуре;
- связанный навык читается из канонического `SKILL.md`;
- отдельный агент запускается штатным инструментом Codex, если процедура или
  оператор это требуют; ему передаются пути к общим правилам и конкретная задача.

Если инструмент отсутствует, обозначь точный недоступный шаг. Не выдумывай
результат подстановки, `/doctor`, SSH, снимка или работы субагента.

## Хуки: транспорт и границы

В Codex `scripts/runtime/codex_hook.py` нормализует прочитанный журнал во временный
Claude-совместимый JSONL, вызывает существующую политику и передаёт её JSON-вердикт.
Временный файл удаляется тем же процессом; журнал движка не меняется. Временный
файл содержит приватный текст, поэтому не публикуй и не сохраняй его в git.

Для подтверждений в Codex признаются **только** `event_msg/user_message` основной
сессии. `response_item` с ролью `user` может содержать инструкции среды, поэтому
он никогда не подтверждает операцию. Ответы агента, результаты инструментов и
задания/журналы субагентов тоже не подтверждают. Неизвестный формат или недоступный
журнал оставляет опасную операцию заблокированной. В субагенте нужен доступ к
настоящему журналу основной сессии, предоставленный движком; не создавай «копию
подтверждения» руками. Если движок этого не предоставляет, операцию выполняет
основной агент после штатной процедуры согласования.

`apply_patch` переводится в список изменённых файлов и добавляемых строк для
гейта BACKLOG; обычные команды и code mode проверяются замком красной зоны.
Stop-хук учитывает команды и правки inventory в текущем ходе. Как и в Claude,
сторож inventory напоминает один раз, а при отсутствии данных работает fail-open.
Ошибка запуска адаптера до операции даёт `deny`, ошибка Stop — явное предупреждение.

Хуки — дополнительная защита, а не полная граница безопасности. Транспорт
`write_stdin` может не вызывать PreToolUse повторно; неизвестный MCP-инструмент или
интерактивная оболочка также не гарантируют покрытия. Не запускай изменяющие
операции через такие пути: используй проверяемую отдельную команду и процедуру
зоны. Codex в облачной оркестрации может не поддерживать локальные command hooks —
не утверждай, что локальные замки там действуют.

## Ретроспектива и проверка выбора навыков

Общий скрипт ретроспективы понимает оба JSONL-формата и сохраняет редакцию секретов:

```bash
python3 .claude/skills/retro/scripts/extract-transcript.py --runtime codex <путь-к-журналу.jsonl>
```

Для Codex путь выбирается явно: самый новый файл может принадлежать другому
проекту или субагенту. Без пути скрипт останавливается. Для Claude прежний вызов
без аргумента сохраняется. Это не импорт и не объединение истории двух движков.

`scripts/run-evals.sh --runtime claude|codex` проверяет выбор навыков соответствующим
CLI. `--estimate` не вызывает модель. Реальный прогон расходует лимит выбранного
продукта; стоимость Codex помечается как неизвестная, а не как нулевая.

## Разработка и обновление

После правки канонического навыка выполни `python3 scripts/sync-codex.py`, затем
`--check` и нужные тесты. Не правь генерируемые точки входа вручную. Политики и
процедуры меняются в общих источниках; транспорт — в `scripts/runtime/`.
Генератор не перезаписывает чужие ручные файлы; устаревший навык сообщает для
осознанного удаления, а не удаляет пользовательский каталог.

При смене движка начни с cold-start и проверь рабочее дерево. Не делай `pull`,
`stash` или переключение версии поверх чужой незавершённой работы. Обновляй мозг
одним процессом; повторное доверие к изменённым хукам оформляется в Codex.
