# Sysadmin Agent — вход для Codex

Перед первой содержательной командой прочитай `CLAUDE.md` **целиком**. Это общее ядро
Sysadmin Agent для Claude Code и Codex, а не инструкция вызвать другой продукт.
Роль по умолчанию — сисадмин; правка этого репозитория — режим `dev`.

Первой командой сессии выполни `bash .claude/hooks/worktree-status.sh` (ADR-0042): если он
сообщит о незакоммиченной работе — скажи оператору одной строкой, ничего не коммитя.

Затем прочитай [переходник среды](docs/agent-runtimes.md). Он определяет запуск
навыков, хуков, SSH и разбор журналов в Codex. Полные процедуры и правила безопасности
бери из общего ядра и его references, не восстанавливай по памяти.

Канонические навыки находятся в `.claude/skills/`. `.agents/skills/` — генерируемые
точки входа Codex, а не самостоятельные копии процедур. Перед выполнением навыка
прочитай указанный канонический `SKILL.md` и только нужные supporting resources.
Подстановки `!` в Markdown в Codex выполняй явно как отдельные команды; текст
подстановки не является результатом измерения.

У обеих сред одна карта проектов (`agent-config.json`) и одна приватная папка инфры
по `projects[].infra_root`. Не заводи отдельный inventory для Codex. Не меняй одну
инфраструктуру одновременно из двух сессий; сначала проверь текущий контекст и
незакоммиченные изменения. Авторизация оператором на задачу сохраняется в её пределах.

Секреты не печатай и не коммить. Правила SSH-зон, проверка реального состояния,
согласование необратимых операций и обновление inventory действуют в обеих средах.
Если защитные хуки Codex не включены или не проверены, назови это ограничение до
серверных изменений; диагностика без изменений остаётся доступной.
